    1. Problem framing

    The decision is which webpages should enter editorial review first. One row represents one webpage, and the output is a ranked refresh-priority score with an action label. A content or SEO editor can use the queue to inspect search intent, freshness, content quality, and on-page metadata. A wrong positive can waste editorial time; a wrong negative can leave a declining page unreviewed. Data and ML are useful because the dataset contains many pages and multiple signals that are difficult to combine consistently with one manual rule.

    2. Data safety

    The analysis uses `content_refresh_anonymized.csv`. Pseudonymous `client_id` and `content_id` fields are not model features; `client_id` is used only for grouped validation and `content_id` only for the final review queue. `trend_direction` and `trend_pct` are deliberately excluded as label-derived fields. The target is constructed from recent and previous 30-day session windows, so those session windows and matching 30-day impression/click comparison fields are also excluded from the feature set. No client names, domains, URLs, private queries, or credentials are used.

    3. Baseline

    The baseline is a transparent additive score. It gives points for low CTR, poor average position, low engagement, stale content, and high search volume. All thresholds are estimated from the training split only. On the grouped validation split, baseline Precision@10 was **0.40** and Precision@20 was **0.45**.

    4. Model / analysis

    A Random Forest classifier ranks an observed decline proxy. The proxy is positive when `sessions_last_30d` is at least 20% lower than `sessions_prev_30d`, with a non-zero previous window. This is not a direct refresh-success label. The model uses allowed numeric and categorical search, engagement, freshness, content, and metadata features while excluding IDs, trend fields, and the 30-day comparison fields used directly in target construction.

    5. Evaluation

    Validation is grouped by pseudonymous client so a client's rows do not appear in both training and validation. The validation base rate was **0.3021**. The model and baseline were evaluated on the same held-out rows. Model Precision@10 was **0.90** versus baseline **0.40**; model Precision@20 was **0.90** versus baseline **0.45**. Model ROC-AUC was **0.5013** versus baseline **0.5800**. Model Average Precision was **0.3044** versus baseline **0.3589**.

    The error analysis checks false positives among the top-ranked rows. These errors are expected because the proxy is imperfect and the dataset does not include every factor that may affect performance.

    6. Interpretation

    The most important observed model signals included: numeric__scroll_rate, numeric__char_count, numeric__word_count, numeric__content_age_days, numeric__users_90d. Feature importance describes how the trained model used the available variables; it does not establish a causal effect. A useful negative result is that a high model score alone is not enough to justify automatic content changes.

    7. Recommendation

    Use the ranked queue as a human-review worklist. High-scoring pages are labelled `REFRESH_NOW`; the current top-20 queue contains action labels based on the held-out model scores. Each recommendation includes reason codes such as low CTR, poor position, low engagement, stale content, or high search volume. The editor should verify the page before changing it. Confidence is directional, and a recommendation may be wrong if the observed decline does not persist, the proxy does not represent a true refresh need, or an unobserved factor explains the pattern.

    8. Reproducibility

    Use Python with `pandas`, `numpy`, `scikit-learn`, and `matplotlib`. Run `capstone_completed.ipynb` from top to bottom with `content_refresh_anonymized.csv` available locally or uploaded in Colab. The random seed is **42**. The notebook generates the model-vs-baseline table, feature-importance table/chart, leakage audit, and top-20 recommendation CSV.
